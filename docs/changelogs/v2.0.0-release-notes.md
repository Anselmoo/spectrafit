# v2.0.0 Release Notes

SpectraFit v2.0.0 is the first release that consolidates the migration to typed
Pydantic-centered runtime contracts, a subcommand-based CLI, and an external
plugin framework.

## Highlights

- canonical validated input via `UnifiedFittingConfig`
- canonical runtime/export result ownership via `FitResult`
- subcommand CLI (`fit`, `validate`, `convert`, `report`, `init`, `new-config`,
  `plugins`, `jupyter`)
- external-only plugin protocol with repository template support
- typed notebook/report bridges with legacy seams pushed to explicit boundaries

## Upgrade path

1. Review the [breaking changes](v2.0.0-breaking-changes.md).
2. Follow the [migration guide](../interface/migration-v2.md).
3. Use `scripts/migrate_v1_config.py` to convert legacy config payloads to the
   canonical v2 shape when needed.
4. Re-run validation with:

```bash
uv run --group dev pytest tests/ -q
```

## New features

- CLI/runtime configuration resolution shared across commands
- top-level Jupyter interface (`spectrafit jupyter`)
- plugin discovery + command registration for external entry-point packages
- repository-owned external plugin template under `examples/plugin_template/`
- `py.typed` marker for typed package consumers
- clearer module ownership and runtime boundary guidance across the v2 surface

## Release verification

- touched-file Ruff checks passed for the Phase 4–7 change set
- release-candidate test validation was run as part of the migration hardening

## Benchmark status

An apples-to-apples minimal CLI benchmark was run against `v1.4.2` using the
same local two-column example spectrum, a Gaussian plus linear background model,
`leastsq`, and isolated temporary environments for both versions.

- current `v2.0.0` median runtime: `1.4628s`
- `v1.4.2` median runtime: `1.4788s`

This is effectively near-parity on the sampled single-fit workload, with the
current runtime slightly faster by about 1%.
