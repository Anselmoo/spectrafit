# Examples Folder + Synthetic Data Artifacts

## Summary

**Spike Objective:** Design and create a self-contained `examples/` directory that ships input
files (v2 TOML schema), pre-generated CSV data, and PNG fit-quality artifacts so that users and
CI/CD can immediately verify the engine works on realistic spectral data.

**Why This Matters:** Without example input files, new users have no reference for the v2 TOML
schema (`[[components]]` flat format), and CI cannot run a smoke-test that demonstrates the full
pipeline end-to-end with realistic data. The community specifically needs:
(a) working input files they can copy-edit, and
(b) fit-quality PNG exports as reviewable artifacts to confirm numerical accuracy of the engine.

**Timebox:** 1 sprint

**Decision Deadline:** Before `v2.0.0` documentation is updated and the branch is opened for PR.

---

## Research Question(s)

**Primary Question:** What examples, synthetic data generator, and CI artifact strategy best
demonstrate SpectraFit's v2 capabilities with minimal maintenance burden?

**Secondary Questions:**

- Which spectral scenarios should be in `examples/` (single Gaussian, multi-peak, constrained,
  global fitting, background subtraction)?
- Should `examples/` data CSVs be committed (static) or regenerated by a `poe` task?
- How should PNG fit exports integrate with CI — as uploaded artifacts or as committed reference
  images with a pixel-tolerance comparison?
- Should `examples/` serve double duty as integration test fixtures?
- What's the minimal `spectrafit` API call needed to produce a PNG without the Jupyter plugin?

## Technical Context

**Related Components:**
- `prototype/synth_data.py` — canonical synthetic data generator (self-contained, portable)
- `prototype/input.toml` — v2 schema reference (2 peaks + background + constraints)
- `spectrafit/core/fitting_config.py` — `UnifiedFittingConfig.from_file()`
- `spectrafit/models/registry.py` — `REGISTRY` (available model names)
- `spectrafit/core/pipeline.py` — `FittingPipeline` (full fit execution)
- `tests/validation/` — existing validation test structure to extend/align with
- `.github/workflows/python-ci.yml` — `validation` job that uploads artifacts

**Dependencies:**
- CI/CD spike must resolve before `validate-examples` poe task is added to the CI job
- `FittingPipeline` must be stable (Phase 5 complete ✓) before examples can run the full pipeline
- `spectrafit/plotting.py` API must be confirmed or added (currently deferred per architecture docs)

**Constraints:**
- `examples/` data CSVs should be committed (deterministic, seed-fixed) — avoids CI flakiness
- PNGs committed as reference images risk large diffs; prefer CI-uploaded artifacts only
- Example input TOML must use v2 flat `[[components]]` format (not v1 peaks dict)
- Scripts in `examples/` or `scripts/` must have zero `prototype.*` imports
- Must work on Python 3.10–3.13

## Proposed Example Structure

```
examples/
├── README.md                       # Overview of all examples + how to run
├── basic/
│   ├── README.md                   # Single Gaussian fit
│   ├── input.toml                  # v2 schema: 1 Gaussian + linear background
│   └── data.csv                    # 200-point synthetic spectrum (seed=42)
├── two-peak-constrained/
│   ├── README.md                   # Cross-component constraints (dot-notation expr)
│   ├── input.toml                  # p1 (Gaussian) + p2 (Pseudo-Voigt, center=p1.center+1.0)
│   └── data.csv                    # 200-point synthetic spectrum
├── multi-peak-background/
│   ├── README.md                   # 3 peaks + polynomial background
│   ├── input.toml                  # p1/p2/p3 + bg (quadratic)
│   └── data.csv                    # 300-point synthetic spectrum with curved background
└── scripts/                        # (or in top-level scripts/)
    └── generate_examples.py        # Regenerates all data.csv + runs fit + exports PNG
```

## Decision

### Recommendation

_To be filled in after investigation._

**Preliminary recommendation:**

1. Port `prototype/synth_data.py` logic into `scripts/generate_examples.py` with zero
   `prototype.*` imports; use `spectrafit.models` directly for component specs
2. Commit static CSVs (deterministic seed) — regenerated only when physics changes
3. PNGs NOT committed; uploaded as CI artifacts per-run for human review
4. Add `poe generate-examples` + `poe validate-examples` tasks to `pyproject.toml`
5. Add `validate-examples` to the `validation` CI job (alongside existing `tests/validation/`)
6. Start with 2 examples (`basic/`, `two-peak-constrained/`); add `multi-peak-background/` in v2.1
